# NovaBot v9 — Render Free / Phone Pairing

This version replaces whatsapp-web.js + Chromium with Baileys WebSocket to reduce memory use. Baileys supports phone-number pairing and does not require Selenium/Chromium.

## Important Render Free limitation
Render Free has an ephemeral filesystem. Local Baileys auth under `AUTH_PATH` can be lost on restart/redeploy/spin-down, so this build is intended for testing and may require pairing again after a restart. Render Free also spins down after 15 minutes without inbound traffic.

## Connection
Open `/` and enter the WhatsApp number in E.164 digits only, e.g. `2348012345678`. No QR is displayed or generated by the app UI. Copy the pairing code and enter it in WhatsApp → Settings → Linked Devices → Link a device → Link with phone number instead.

## Dashboard
The connection page contains no dashboard link. The server prints `dashboard_token=...` in Render logs. Open `/dashboard?token=THAT_TOKEN`.

`.sticker` is intentionally disabled in this Free-tier build to avoid adding media-processing dependencies and RAM pressure.

## Environment
`BOT_NAME`, `PREFIX`, `OWNER_NUMBER`, `AI_ENABLED`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `AUTH_PATH`, `DATA_PATH`, `DASHBOARD_TOKEN`, `AUTO_CONNECT`, `PORT`.

Set `AUTO_CONNECT=true` only if you want the app to attempt reconnecting when local auth exists. On a fresh instance leave it false so the phone-number page controls the first pairing.

## Architecture
WhatsApp ↔ Baileys WebSocket ↔ NovaBot + Socket.IO read-only dashboard. No Chromium.
